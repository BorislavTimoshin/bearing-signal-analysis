# Как обновить COS1 после следующего задания Work

1. Передайте Work последнюю локальную версию, включая ваши изменения: Git bundle (например, `git bundle create current.bundle --all`) плюс нужные данные вне Git. Сообщите текущую версию и локальные настройки. Старый ZIP в чате не доказывает отсутствие локальных правок.
2. Сначала сохраните свою работу отдельным коммитом, а данные — резервной копией. Не коммитьте большие массивы и .venv.
3. Попросите следующий релиз с CHANGELOG, базовым commit ID, проверенным bundle/patch, миграцией и тестами. Не применяйте патч к неизвестной базе.
4. Полученный bundle сначала проверьте `git bundle verify update.bundle`, затем импортируйте в отдельную ветку и сравните изменения. Объединяйте через Git; конфликты разрешайте до запуска экспериментов.
5. Установите зависимости новой версии, выполните audit, pytest, validate и Notebook. Сохраните предыдущий релиз до успешной проверки.

## Первое открытие истории

В релиз включён `COS1_history.bundle`. В соседнюю новую папку выполните `git clone COS1_history.bundle COS1_git`. Затем перенесите из ZIP исключённые из Git папки legacy, data, results/figures, сохраняя пути. Bundle сам по себе не содержит экспериментальных массивов. Либо работайте непосредственно в распакованном ZIP, создав локальную историю через git init / git add / git commit; это будет новая история, не история bundle.

## Без Git

Распакуйте новый ZIP рядом со старым, а не поверх него. Сравните CHANGELOG и migration_map.csv. Переносите пользовательские конфигурации и изменения кода только после сравнения; исходники с одинаковыми именами сверяйте по SHA-256. Ранее рассчитанные результаты сохраняйте отдельно. Старый каталог удалять не нужно. Не копируйте старую .venv: создайте новую.

## Миграция этапа I → 0.2.0

Аудит сохранён в legacy/stage1 без изменения файлов. Полная таблица соответствия — results/manifests/migration_map.csv. Исторические абсолютные ссылки в старых отчётах являются архивными; текущие команды используют относительные пути новой структуры. Новый код не модифицирует legacy. Отдельные файлы нормировки пока отсутствуют намеренно.
