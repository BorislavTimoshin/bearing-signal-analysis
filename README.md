# COS1 0.2.0 — исследование вибрации подшипников

Проект объединяет обзор девяти вариантов датасетов (этап I) и технический пилот FFT-ресемплинга пяти наборов (этап II). Это исследовательский проект, не диагностическая система. Нормировка, Баттерворт, обучающая сегментация, аугментация и обучение не реализованы.

## Быстрый старт в Windows / PyCharm

Распакуйте ZIP в новую папку. Откройте именно каталог с `main.py` через File → Open. Рекомендуется Python 3.12, проверка выполнена на Linux; Windows отдельно не тестировалась.

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev]"
.venv\Scripts\python main.py --help
.venv\Scripts\python main.py audit
.venv\Scripts\python main.py all
.venv\Scripts\python -m pytest
.venv\Scripts\ruff check .
.venv\Scripts\ruff format --check .
```

В PyCharm Settings → Project → Python Interpreter выберите `.venv/Scripts/python.exe`. Для Run Configuration выберите `main.py`, аргумент `all`, рабочий каталог проекта. На Linux/macOS используйте `python3.12 -m venv .venv`, затем `.venv/bin/python` и `.venv/bin/ruff`. Альтернативная установка: `python -m pip install -r requirements.txt`; файл ссылается на единый источник зависимостей pyproject.toml.

## Порядок вычислений

Исходные данные → загрузка с SHA-256 → проверка сетки → FFT-ресемплинг → статистики и спектральная проверка → рисунки → таблицы.

- `main.py` — только разбор команд.
- `src/cos1/data.py` — корень проекта, реестр и загрузка NPY/текстового HUSTbearing. Чтение исходников, без сетевых запросов.
- `time_grid.py` — точная рациональная длина M. Нецелый результат вызывает ошибку: автоматического округления нет.
- `resampling.py` — единственный рабочий вызов scipy.signal.resample.
- `analysis.py` — определения статистик и численные критерии.
- `spectrum.py` — формула спектра предыдущего этапа, перенесённая без изменения математики.
- `plots.py` — реальные осциллограммы и спектры.
- `pipeline.py` — порядок операций, файлы результатов.
- `configs/records.json` — все 17 входных рядов и их происхождение.
- `data/processed/` — новые NPY, исходники сюда не записываются.
- `results/tables/` — манифест и проверки; `results/figures/` — 17 рисунков.
- `reports/stage2/` — отчёт, контекст и план следующего этапа.
- `legacy/stage1/` — неизменённый комплект аудита и прежних результатов, включая исходные сигналы. Ради сохранения относительных ссылок он остаётся целиком; рабочая программа читает данные прямо оттуда, без второй копии в data/raw.
- `tests/` — контролируемые математические тесты; `notebooks/` — воспроизводимый учебный запуск.

`audit` проверяет входы; `resample` создаёт NPY и таблицы; `validate` заново проверяет сохранённые выходы; `figures` строит рисунки из сохранённых выходов; `all` делает ресемплинг, проверки и рисунки. Повторный запуск заменяет только одноимённые результаты этапа II, не исходники, не создаёт временных копий каждого запуска. Перед ручными экспериментами сохраните нужные результаты в отдельной папке.

## Notebook

Откройте `notebooks/02_fft_resampling.ipynb`, выберите kernel `.venv`. Если PyCharm не предоставляет интерфейс Notebook, запустите `python -m jupyterlab` в корне проекта. Регистрация ядра: `python -m ipykernel install --user --name cos1 --display-name "COS1 Python"`. Выполните Restart Kernel and Run All. Notebook импортирует функции проекта и не содержит второй реализации ресемплинга.

## Данные и ограничения

CWRU: 4 фрагмента, 12/48 кГц; Paderborn: 2, 64 кГц; MFPT: 3, 48,828/97,656 кГц; JNU: 4, 50 кГц; HUSTbearing: 1 фрагмент 25,6 кГц и полная запись 10,24 с X/Y/Z. Всего 17 рядов, но 14 исходных групп; HUST X перекрывается с фрагментом. Независимость физических подшипников не установлена. HUST-Hanoi остаётся только в обзоре и не подменяет HUSTbearing.

При повышении CWRU 12 кГц информация выше 6 кГц не появляется. Для последующего фильтра до 10 кГц нужно изменить набор исходных записей или согласовать полосу. Частота вращения не меняется. Полные пять датасетов не скачивались.
